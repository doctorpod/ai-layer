Install wiring install-target.sh · install-skills.sh

The layer lives once on this machine. Each project gets an _AI/ folder of symlinks, so an edit here reaches every install at once. Project context stays in the project; the code repo's work folders live in the vault.

Session boot and dispatch how a request becomes a workflow

Two ways in: a trigger phrase matched against the table in AI.md, or a slash command whose stub only says “read and follow <path>”. Either way the workflow file holds all the logic.

Code delivery: ticket to merged PRs _AI/delivery/work/<key>/

The key (ticket ID or slug) names the work folder and sits in the branch name, so workflows find the folder on their own. Workflows only ever set a slice to planned or in progress; the rest of its state is yours.

Vault loop: notes in, NEXT.md out heartbeat · frontier · knowledge bases

Input notes are what makes things change. Heartbeat moves the small facts (logistics, status) onto the tracking surfaces and threads tasks; anything that changes what's true about a subject waits for a debrief, which is the only route into a wiki besides ingest.

Writing a piece brief.md · guide/ · output.md · assets/

Gatherers fill guide/; you write output.md. Nothing here drafts your prose. Beats and polish are the only things that touch output.md, and only in their own narrow way.

Principles docs/PRINCIPLES.md

  1. The owner decides, AI drafts.
  2. Diagnostic means diagnostic. Assessors never edit.
  3. Propose, then apply on confirmation. One question at a time.
  4. Write only where you're allowed. The allowlist is exhaustive.
  5. Hand-owned files change only on an explicit say-so.
  6. Every wiki claim traces to its source.
  7. Be honest about what's AI-generated.
  8. Fix what you find, not just what you touched.
  9. Keep the planning layer out of the product. No _AI/ in shipped code.
  10. Shape output for the reader.

Patterns and anti-patterns

  • Rubric: check against a fixed external standard.
  • Gatherer: creates notes as pending, appends, never drafts.
  • Log inputs, derive the rest: write facts once; compute views.
  • Toolbox, not pipeline: small tools you pick, not a forced sequence.
  • ✗ Dead-end state (roach motel): a state nothing ever moves out of.
  • ✗ Stored derived state: saving what should be computed.

Docs drift
